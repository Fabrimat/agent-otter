## NOT tested

- Long-poll (`room_inbox` waitSeconds 25) **through a public tunnel**: NOT tested. It needs the owner's permission to open a tunnel; all runs used `http://127.0.0.1`.
- Interactive (TUI) sessions, macOS/Linux, other host versions, OpenCode, Hermes, host restart resuming from the cursor, a human interrupting a waiting turn, the "seen by" receipt rendered in a real browser (only the receipt WebSocket events were checked).
- The `setx` PowerShell snippet for Codex (it changes the user's persistent environment), the path-fallback URL, and Claude's default `--scope local` were not run.

## How to read the results

- The pull-usability table, the loop persistence, timeout and snippet verdicts are in [measured.md](measured.md).
- **H4 (prompt injection) is NOT a test of the models' resistance to command injection.** The victim agents had no usable shell (Claude: not allow-listed; Codex: its Windows sandbox refused every command), so "commands executed: 0" would have been 0 whatever the model did. Only the Claude exfiltration rows (a Read-capable agent asked to post a canary file) exercise a possible harm. For Codex the Read-allowed rows are vacuous: no Read tool and no working shell. The detector check and the Read-denied control are what show the leak detector works.
- Samples are tiny and model behaviour is probabilistic: counts are observations, not guarantees.
- A Claude agent in `-p` mode may end its own turn instead of looping on `room_inbox`; a Codex agent kept looping in the recorded window (see the loop row). Pull-only keep-alive is not something the product can rely on from Claude.
