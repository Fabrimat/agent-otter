# @agent-otter/e2e-hosts

Opt-in tests against the real Claude Code and Codex CLI installed on this machine (H1 join, H2 join, H3 cross-vendor, H4 prompt injection, snippet checks, Codex quirks). They spend the owner's vendor usage, so they never run in `pnpm -r test` (that only prints SKIPPED).

Run everything (a full run was observed to take about 11 minutes; Claude cost guard `HOSTS_MAX_USD`, default 2.00):

    RUN_HOSTS=1 pnpm --filter @agent-otter/e2e-hosts hosts

PowerShell: `$env:RUN_HOSTS = "1"; pnpm --filter @agent-otter/e2e-hosts hosts`

Only the snippet scenarios (writes into its own run dir; set `HOSTS_RUN_ID` to an existing run id to refresh that run, then `node scripts/report.mjs <id>`):
`cd e2e-hosts; RUN_HOSTS=1 npx vitest run --config vitest.config.ts test/snippets.test.ts`

Results: `results/latest.md` (committed summary, generated by `scripts/report.mjs` from `results/<run id>/*.json`), `results/<run id>.json` (ignored). The same report is published as `docs/hosts/measured.md`; every number in `docs/hosts/` comes from there.

## Rules the harness enforces

- The server under test is started in-process and listens on `127.0.0.1` only (asserted). No tunnel, proxy or port forward.
- No permission-bypass flags. Per-run configuration only (flags, `-c` overrides, temp dirs, env vars).
- Global-config guard: before and after every test file the harness hashes (sha256) exactly these: the `mcpServers` sections of `~/.claude.json` (top level and per project; the rest of that file is rewritten by Claude itself, and a transient parse error is retried), `~/.claude/settings.json`, `~/.claude/CLAUDE.md`, `~/.codex/config.toml`. The run fails if any hash changed. NOT covered: the rest of `~/.claude/` (sessions, history, caches) and everything else in `~/.codex/` (auth.json, sessions, sandbox state).
- Cost guard: each Claude run reserves its per-run budget (default 0.25 USD) in `results/<run id>/spend.jsonl` before launch and is booked at the cost the host reports; runs with no reported cost (timeouts) stay counted at the reserved budget. **The cost guard covers Claude only.** Codex does not report cost and has no cap beyond the per-run test timeouts (about 30 Codex runs per full pass). Codex victims run with the shell tool disabled, except the single explicit shell probe in `test/h4.test.ts`.

## Against a deployed server (remote mode)

The same scenarios that do not read server internals (H1, H2, H3) can run against a deployed server with the real CLIs on this machine. https only; the create key goes through the environment, never to disk:

    RUN_HOSTS=1 HOSTS_REMOTE_URL=https://your.host HOSTS_CREATE_KEY=... npx vitest run --config vitest.config.ts test/h1h2.test.ts test/h3.test.ts

Set `HOSTS_RUN_ID=remote-...` so the results do not mix with the loopback run. This relaxes the "loopback only" rule above for the server under test only; everything else (cost guard, global-config guard) still applies. Observed against a Coolify deployment behind Cloudflare and Traefik: H1, H2, H3, H3b and H3c pass.
